PROSSIMI PASSI: VERSO PRIMI UTENTI E OLTRE

====================================================================
A. BLOCCANTI TECNICI (in ordine, ognuno sblocca il successivo)
====================================================================

1. PERCORSI ASSOLUTI + CONFIG
   Oggi modelli e sessioni sono relativi alla directory corrente
   (`MODELS_DIR = "models"` in src/model.rs:14, `default_value = "sessions"`
   in src/cli.rs:37). Installato il binario, l'app cerca i file nel posto
   sbagliato.
   - dati in ~/Library/Application Support/<nome-prodotto>/{models,sessions}
   - ordine di risoluzione: flag > config > default assoluto
   - fallback alla cwd solo per la dev mode
   Fatto quando: `scrib start` funziona da qualsiasi
   directory, sia dal binario installato sia da `cargo run`.

2. NOME DEL PRODOTTO + BUNDLE ID
   Non è design: decide bundle ID, permesso TCC, cartella dati, firma.
   Deciderlo dopo i percorsi significa migrare i dati degli utenti.
   `scrib` è il nome del prodotto, del crate e del binario.
   Fatto quando: esiste un nome, un bundle ID (com.<autore>.<nome>) e la
   cartella dati definitiva.

3. CHI POSSIEDE LA SESSIONE
   L'app (a) lancia il binario come sidecar e legge i file di sessione,
   oppure (b) linka la lib Rust? Sono due architetture diverse.
   Da dichiarare prima di scrivere la UI, perché cambia tutto a valle.
   Deciso: (b), lib linkata in-process (docs/adr/0003). Il processo
   dell'app esegue la sessione ed è l'unico proprietario; il CLI resta
   un client, come la UI.

4. MODELLO: SOLO LARGE-V3-TURBO
   - scaricato al PRIMO AVVIO dell'app, non dentro il pacchetto
     (834 MB: nel .dmg significherebbe 834 MB da scaricare prima di poter
     aprire l'app, e ri-caricarli a ogni release)
   - verifica SHA-256 con la tabella già presente in src/model.rs, hash
     in cache per non ricalcolare 834 MB a ogni avvio
   - `--model <percorso>` resta come escape hatch
   - caricato in RAM all'avvio di ogni trascrizione (comportamento già
     attuale, non cambia)
   - rimuovere la macchina dei preset: `ModelPreset`, `ModelPick` e il
     menu interattivo in src/cli.rs (è codice morto con la GUI)
   Fatto quando: `start` senza flag scarica (se manca), verifica e usa
   turbo; nessun prompt di scelta modello.

5. INSTALLAZIONE NON-DEV (priorità: pubblico tecnico)
   - script `curl | sh`: uname -m, download tarball della release,
     `shasum -a 256 -c`, install in `$(brew --prefix)/bin` se brew c'è,
     altrimenti /usr/local/bin con sudo. Nessuna modifica al PATH.
   - tap Homebrew (formula): un file, gratis.
   - NIENTE .dmg per ora: senza firma è inutilizzabile (vedi punto 12).
   - curl non applica la quarantena, il binario è già firmato ad-hoc:
     nessun avviso Gatekeeper.
   Fatto quando: su un Mac Apple Silicon pulito, senza repo clonata,
   `curl … | sh` seguito da `start` produce una trascrizione.

====================================================================
B. PRODOTTO E DISTRIBUZIONE
====================================================================

6. BRANDBOOK MINIMO
   Una pagina, non un PDF: nome, una frase che dice cosa fa, icona, due
   font, tre colori, tono di voce. Prima del sito, perché il nome
   finisce ovunque.

7. SITO + DOCS
   Landing page statica (Astro) su GitHub Pages/Cloudflare:
   - cosa fa il prodotto, punti di forza (locale, privacy, nessun cloud)
   - sezione installazione: per ora script curl + brew, il .dmg quando
     ci sarà la firma
   - sezione documentazione GENERATA dai markdown in docs/, non
     riscritta: una sola fonte di verità

8. APP TAURI
   Shell cross-platform sopra il core Rust (stesso schema di Foresight:
   shell + core nativo), niente browser né server locale.
   Primo giro: sola lettura delle sessioni esistenti (lista, dettaglio,
   export). Poi il live.
   Il binario viaggia dentro .app/Contents/MacOS/, quindi l'utente
   finale non installa niente e non tocca il PATH.
   Prerequisiti (dal punto 3): header WAV ricostruito in recovery,
   `StartOptions` costruito in un posto solo e condiviso con `cli.rs`,
   `list_sessions` nella lib.

9. CORE AUDIO TAPS (sostituisce BlackHole)
   Da fare DOPO lo scheletro dell'app con bundle ID: il permesso TCC
   viene attribuito a chi chiama l'API, se lo sviluppi dal CLI il
   permesso lo prende il Terminale e poi va ri-concesso.
   - macOS 14.4+, `AudioHardwareCreateProcessTap` (API ObjC →
     objc2 o helper Swift)
   - serve `NSAudioCaptureUsageDescription` in Info.plist (non serve
     entitlement fuori dal sandbox: le app Tauri non sono sandboxed)
   - aggregate device tap + uscita corrente = senti e registri insieme
   - BlackHole resta come fallback documentato sotto 14.4
   - NON impacchettare BlackHole: è GPLv3
   Da fare PRIMA un grilling per fissare: chi cattura, comportamento
   sotto 14.4, convivenza col fallback, cambio cuffie a sessione attiva,
   identità del permesso TCC.
   Fatto quando: una call su Zoom/Meet viene trascritta senza driver
   installati e senza toccare Audio MIDI Setup.

10. ALTRI MODELLI (dopo, non ora)
    Il modello diventa un elenco selezionabile dall'app, con download
    on-demand. Rimandato finché turbo non è stabile per settimane.

====================================================================
C. VINCOLI E GATE
====================================================================

11. DEV MODE INVARIATA
    `cargo run --release -- …` continua a funzionare per lo sviluppo.

12. FIRMA E NOTARIZZAZIONE — GATE DI LANCIO DELL'APP
    Non è un'appendice: senza firma un .app scaricato da Safari non si
    apre ("danneggiato") e non esiste workaround decente per un utente
    non tecnico. Apple Developer Program 99 $/anno + hardened runtime +
    notarytool + stapler, automatizzabile in GitHub Actions.
    Oggi si rimanda perché non c'è ancora un .app da distribuire.
    Da fare PRIMA del primo utente consumer, non dopo.
    Nel frattempo: script curl (nessuna quarantena) e brew tap.
